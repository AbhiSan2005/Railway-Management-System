Database Design & Theoretical Normalization Specification

Detailed documentation explaining the translation of the ER diagram, functional dependencies, and integrity constraints.

1. Simplification Strategy of the Given E.R. Model

The raw E.R. diagram contains 10 entities, multiple weak entities, composite attributes, and administrative models. The relational schema streamlines these components without losing data integrity:

Original E.R. Element Construct Type Relational Translation & Normalization
PASSENGER.address Composite Attribute Decomposed into four atomic attributes: street, city, state, pincode (1NF compliant).
PASSENGER.age Derived Attribute Removed redundant stored column; computed dynamically using GENERATED ALWAYS AS (TIMESTAMPDIFF(YEAR, dob, CURDATE())) VIRTUAL.
PASSENGER.phone_numbers Multivalued Attribute Primary contact preserved on passengers; multi-line contacts partitioned to child table passenger_phones(passenger_id, phone_number).
SCHEDULE Weak / Associative Entity Primary key defined as composite (train_id, stop_sequence) with foreign key to stations(station_id).
SEAT & COACH Hierarchical Dependent Entities Composite key (coach_id, seat_number). The tickets relation stores coach_id and seat_number for efficient indexing.
EMPLOYEE Administrative Entity Retained in the physical SQL schema, but isolated from the transactional reservation path to ensure peak query performance.

2. Progressive Normal Forms Analysis

1NF

First Normal Form

Attributes must hold strictly atomic values, with no repeating groups or composite structures.

  • Decomposed composite address into atomic column structures.
  • Decomposed multivalued phone lists into relationally isolated tuples.
  • Eliminated storage of derived age to ensure temporal consistency.
2NF

Second Normal Form

Must be in 1NF and have zero partial functional dependencies on any candidate key.

  • In schedules (train_id, stop_sequence), arrival and departure times depend fully on the composite key.
  • Station descriptors (name, code, city) are isolated in stations, preventing partial dependency anomalies.
3NF

Third Normal Form

Must be in 2NF and eliminate all transitive dependencies (X → Y → Z).

  • In tickets, only surrogate keys (passenger_id, train_id) are stored.
  • Denormalized names or station names are excluded, preventing update and deletion anomalies.
BCNF

Boyce-Codd Normal Form

For every non-trivial functional dependency X → Y, X must be a superkey.

  • All determinants in every relation are candidate keys or primary keys.
  • Zero redundant functional dependencies exist across any table.

3. Relational Integrity Constraints

PRIMARY KEY
Enforces entity integrity (uniqueness and mandatory non-null values across surrogate and composite keys).
FOREIGN KEY & CASCADES
Enforces referential integrity with ON DELETE CASCADE for child tables and ON DELETE RESTRICT for tickets.
UNIQUE COMPOSITE
UNIQUE (train_id, coach_id, seat_number, journey_date) guarantees an exact seat cannot be double booked.
CHECK DOMAINS
Validates domain invariants: CHECK (fare > 0), CHECK (distance_km > 0), and distinct station pairs.
